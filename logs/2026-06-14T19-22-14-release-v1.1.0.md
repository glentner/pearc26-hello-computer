## Work Completed

### `/release` skill not loading — diagnosis and fix

The user noticed the `/release` skill was not available to the agent even though
`.agents/skills/release/SKILL.md` exists. Root cause: the `description` field in
the YAML frontmatter was an **unquoted scalar** containing colon-space (`: `)
sequences — `WIP: prefixes` and `arguments: squash`. YAML treats `: ` as a
mapping key/value separator, so the parser raised `Psych::SyntaxError: mapping
values are not allowed in this context at line 3 column 53` and the frontmatter
failed to parse. Warp skips skills whose frontmatter does not parse, so the
skill never entered the available-skills list. (The two `latex-integration-*`
skills load fine because their descriptions contain no `: ` sequences.)

Fix: wrapped the `description` value in double quotes (content otherwise
unchanged). Verified with `ruby -ryaml` that the frontmatter now parses
(`keys=["name", "description"]`). This is a useful general tip: skill
descriptions that mention `WIP: ` or any `word: word` construct must be quoted.

### v1.1.0 release

Followed the `/release` skill procedure for a full release (minor bump + tag +
GitHub release):

1. Pre-flight: clean tree, on `wip`, fetched origin + tags, `wip` ahead of
   `main`, `make build` exit 0.
2. Stripped `WIP: ` prefixes on `main..HEAD` via `git filter-branch` (the
   project-mandated tool).
3. Fast-forward merged `wip` into `main` (no `--no-ff`).
4. Annotated tag `v1.1.0` on the merged `main` HEAD.
5. Pushed `main` and the tag; published the GitHub release with hand-curated
   notes consistent with the `v1.0.1` style.
6. Returned to `wip` and force-pushed; `origin/main` and `origin/wip` now point
   to the same commit.

Release contents since `v1.0.1`: camera-ready conference rights/metadata and ACM
CCS 2012 concepts (already on `main`), the `make upload` TAPS packaging target
with the `pdf/` + `Source/` archive layout, and the `/release` skill frontmatter
fix.
